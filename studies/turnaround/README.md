# 从多视图原画到可编辑像素底模

给出同一人物的几张原画，能自动恢复多少可以反复编辑、从任意角度观看的体积？打开 [切片实验室](../../turnaround-lab.html) 可以转动五个样本、编辑任一水平切片、全身换色，并导出和重新导入底模。

## 实测

两张平滑头像分别取自原创动画设定。各自只读正面和正侧面。三个全身角色取自另一张原创像素设定，各读正、侧、背三幅。两组都留出独立绘制的 45° 原画。所有模型设为高 96 格、最多 64 色，两个算法共用同一输入、配准、分辨率与色彩投影。第一种沿各图的剪影取体积交集。第二种在每个水平截面内，将宽度和深度的外角削圆，强度固定为 0.75。

| 独立 45° 视角 | 直接相交的轮廓 IoU | 圆化后的轮廓 IoU | 直接相交 → 圆化的颜色 MAE |
| --- | ---: | ---: | ---: |
| 平滑婴儿头像 | 0.720 | 0.890 | 29.16 → 27.91 |
| 平滑成人头像 | 0.730 | 0.839 | 31.46 → 29.56 |
| 像素成人全身 | 0.787 | 0.821 | 25.42 → 24.18 |
| 像素儿童全身 | 0.771 | 0.783 | 26.15 → 25.18 |
| 像素婴儿坐姿 | 0.746 | 0.816 | 32.27 → 29.26 |

IoU 为前景交集面积除以并集面积，最高为 1。颜色 MAE 只在两张图的共同前景按 RGB 通道计算，取值从 0 到 255，越小越好。输入每幅图以该图的人物高度独立归一化，横向原点预先写进配置。评估时没有再搜索最有利的平移或缩放。画稿中的 45° 是美术设定的方向，视角和姿态存在画师绘制时的偏差。替换留出图能改变分数，输出的几何和颜色逐字节相同。[逐幅像素计数及指标](results.json)

**最明显的失败在脸上。** 婴儿帽子的大轮廓已接近原画，45° 的帽沿到脸颊却有折痕。成人的远眼和嘴角出现双线。全身婴儿可看出坐姿，侧发和腿旁会伸出细长的水平像素。两个平滑头像没有背面观测，转到背面显示的是算法补出的形体和颜色。这些样本尚未测量美术师的返修时间或主观偏好。

我们还单独交换了两块同色立方体的前后位置配对。两种摆法的正、侧、背三幅投影逐像素相同，45° 的投影却有 24 和 9 个像素，交集为零。实际的婴儿发梢也出现了这种歧义，一幅图里的一像素发梢与另一幅图的两像素发束交叉，形成斜视时才露出的假尖刺。

另做了一个二维实验，在同样的 52×45 网格与 16 色预算下比较普通量化、保护轮廓与五官、按材质预留颜色。保护眼部能留下亮点，给衣服单独留色能保住灰绿衣服，眼口地标与材质色阶由人标定。每张图使用自己的原始视图，45° 只用于检验共享色板的适用性。脸颊仍有斑块，独立像素设定稿还重新设计了嘴形和服装。[二维像素化对照](pixel-translation.webp)

## 转换接口

在安装了 NumPy 和 Pillow 的 Python 3 环境中，从仓库根目录运行以下命令。

```sh
python3 tools/turnaround_to_slices.py studies/turnaround/smooth-baby.json --out /tmp/pine-baby --rounding 0.75 --colors 64
```

也可以在 Python 中调用 `convert(manifest, out, rounding=.75, colors=64)`。命令与函数均生成 `model.json`、`metrics.json` 和每个命名视角的投影、对照 PNG。模型文件可以直接在实验室里打开。

| 输入字段 | 约定 |
| --- | --- |
| `format`、`height` | `pine.turnaround/1`。模型人物高度 4–256 格，默认 96 |
| `source`、`views[].source` | 相对配置文件的图片路径。可共用图集或每个角度各用一张图片 |
| `views[]` | 每个视角包含唯一 `id`、角度 `angle`、矩形 `crop`、用途 `role`。重建至少需要两个投影方向不平行的输入。正面配背面仍缺少深度 |
| `angle`、`crop` | 正面为 0°，90° 时鼻子朝屏幕右，180° 为背面。矩形格式为左、上、右、下，右和下不包含在裁切内 |
| `originX` | 可在每幅视图设置旋转轴在整个裁切宽度中的位置，范围 0–1。缺省取前景包围盒中心 |
| `role` | `input` 用于建模取色。`holdout` 可选，仅在模型确定后打开用于比较 |
| `alphaMask`、`background` | 支持与源图相同尺寸的单通道前景遮罩或自带透明通道。纯色底可用 `{"rgb":[206,198,193],"tolerance":30}` 提取前景。可在单个视角覆盖配置 |

转换先把每幅图抠出并对齐，沿高度逐层重建。表面从朝向相近且可见的输入取色，所有切片共用一张索引色板。带纹理背景、透视镜头或视图间换了姿势时，先抠图并校对视图。仓库内平滑设定配有预制遮罩，每个裁切独立分割。转换过程无需 OpenCV。重新制作此遮罩可运行 `python3 tools/mask-turnaround-portraits.py`，这一步额外需要 OpenCV。

输出 `pine.slices/1` 带有 `dimensions: [nx, ny, nz]`、十六进制 RGB `palette` 和 `runs`。每段 `[z, y, xStart, xEnd, colorIndex]` 占据一个闭区间，索引从 0 开始，空格省略。x 向面前、y 向正面屏幕右、z 向上。色板的第零项也是一个可见色。读写器可改变一格或一种色，再无损还原其他格。当前底模保存的是静态姿态、体积与颜色。骨骼、可换的发型与服装、可眨眼的眼睑需要后续拟合和分件。[平滑头像输入](smooth-baby.json) · [全身输入](baby.json) · [输入与输出的 JSON Schema](formats-v1.schema.json)

```sh
python3 tests/test_turnaround.py
```

## 架构建议

1. **美术创作的起点改为原画。** 先定角色在游戏尺寸的脸与身形，尽量使用同姿态、同光照与相似焦距的转面图。原画、分割、校正点及原始底模均能独立保存。用一张完全留出的视图比较每次改动。
2. **先拟合眼、耳、鼻、口、下巴和肩髋。** 用正、侧视图上的少量地标同时约束已有分龄骨架与脸部参数。给有体积的眼睑、鼻和唇分别使用局部像素笔触。先在婴儿头像测试眨眼和转头，再将坐姿的肩、髋、足跟对准全身图。
3. **等样本能动，再接入人物工坊。** 头发、皮肤和衣物各用自己的色阶和部件编号，导出标准人物配方。用未参与拟合的新角色做复验，统计每个可用角色需要人工补多少处、花多少分钟，同时看 64 / 128 像素和中间角度。此后再决定是否替换整套随机人物的创作流程。

轮廓可以约束模型能占据的空间，藏在外轮廓里的眼窝、嘴缝和肢体遮挡需要其他信息。多视图颜色约束还需要考虑可见性。[Laurentini，视觉外壳](https://doi.org/10.1109/34.273735) · [Kutulakos 与 Seitz，Space Carving](https://www.cs.cmu.edu/~seitz/course/Sigg00/papers/kutu-ijcv00.pdf)

低分辨率像素创作可以联合决定特征落在哪些格、各用哪些颜色，也可以留出美术约束。已有方法用二维关节投影误差来拟合一个可动人体。我们的分龄骨架可复用这个思路。同步生成补视图是另一种来源，应单独标记其中推测的角度。这三项仅作方法研究。[Gerstner 等，像素抽象](https://cragl.cs.gmu.edu/pixelate/journal.html) · [SMPLify](https://smplify.is.tue.mpg.de/) · [SyncDreamer](https://liuyuan-pal.github.io/SyncDreamer/)
